# MapReduce Lab

Проект рассчитывает частоты навыков по Java-вакансиям из RustFS. MapReduce и DuckDB выполняют расчёт независимо, а их результаты сверяются. ZooKeeper выбирает активного координатора, чтобы при потере его сессии другой процесс продолжил расчёт пар навыков с последнего чекпоинта.

## ZooKeeper HW

### Общий пайплайн

1. **Подготовка данных.** Из исходного набора выбирается последний снимок каждой вакансии. Отобранные Java-вакансии загружаются в RustFS в формате CSV.
2. **Расчёт.** MapReduce и DuckDB независимо считают частоты отдельных навыков, пар и троек. После данные сверяются.
3. **Расчёт с восстановлением.** ZooKeeper выбирает активного координатора. Тот читает CSV из RustFS, считает пары тем же маппером и после каждого чанка сохраняет частоты и число обработанных строк в общей SQLite. Когда сессия приостановленного лидера истекает, запасной координатор получает новую эпоху и продолжает с чекпоинта.
4. **Публикация и сверка.** После возобновления старый лидер пытается записать результат. При `FENCING=0` принимаются обе публикации. При `FENCING=1` получатель проверяет эпоху в транзакции записи и отклоняет устаревшую публикацию. Сценарий сравнивает частоты каждой принятой публикации с эталоном MapReduce.

### Что добавлено для ZooKeeper

- Выбор лидера с тайм-аутом сессии 10 секунд (`src/map_reduce/coordination/election.py`, `src/map_reduce/coordination/coordinator.py`).
- Сохранение прогресса и восстановление расчёта пар из общего чекпоинта (`src/map_reduce/coordination/checkpoints.py`, `src/map_reduce/coordination/coordinator.py`, `src/map_reduce/coordination/publication.py`).
- Проверка эпохи при публикации результата (`src/map_reduce/coordination/publication.py`).
